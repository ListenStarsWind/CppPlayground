# 类和对象：课时二

上一课时用 `Date` 和 `stack` 说明了类、对象、成员访问与 `this`。不过，对象的使用还依赖调用者手动安排：创建日期后调用 `Init`，创建栈后调用 `Init`，使用结束时再调用 `Dest`。

这些操作与对象的存在密切相关。漏掉初始化，对象可能没有可用的初始状态；漏掉资源释放，申请的动态内存就可能泄漏。这一课时从构造函数与析构函数出发，把初始化和清理接入对象的生命周期，再讨论对象复制、赋值和日期运算。

代码继续使用 `wind::Date` 与 `wind::stack`。栈仍以 `stack_data` 表示元素类型，以 `_p`、`_top`、`_capacity` 保存状态，`push`、`Ext` 等接口沿用上一课时的命名与返回值约定。以下代码按小节逐步扩展；同一个函数的不同版本是替换关系，不应同时定义。

本课时主要讨论类的默认成员函数：构造函数、析构函数、拷贝构造函数和拷贝赋值运算符都是其中的重要部分。它们分别参与对象的创建、销毁与复制，有固定的调用时机，不能只当成需要手动调用的普通接口。

这里先建立一个基本认识：对于这些函数，在满足相应条件时，即使没有亲自编写，编译器也会提供默认实现；亲自定义某一项后，这一项就使用自己定义的实现。不同函数的生成条件稍有区别，例如，一旦自己声明了构造函数，编译器就不再额外补一个无参构造函数。下面结合具体代码逐步观察这些规则。

## 构造函数

### 从手动初始化到创建时初始化

上一课时的日期需要这样使用：

```cpp
wind::Date d;
d.Init(2024, 10, 1);
d.Print();
```

`d` 在调用 `Init` 之前就已经存在，但其中三个整数尚未得到有效的日期值。若直接读取这些未初始化的成员，不能把显示出的数字当成有效日期，更不能把“某次恰好显示为 0”当成初始化保证。

![未初始化成员的观察记录之一](https://img.mdwind.online/md/202409251152041.png)

构造函数用于在创建对象时建立初始状态。它的名字与类名相同，不写返回类型，连 `void` 也不写。调用者在对象定义处提供参数，编译器将构造过程接入对象创建，不需要另写一次 `Init` 调用。

对象自身的存储空间与构造过程中申请的资源要分清。例如，局部 `Date` 对象的存储由相应的存储安排提供；构造函数负责把它初始化为一个日期。对于持有动态数组的栈，构造过程中还可以另外申请元素空间，但这块动态内存并不是栈对象本身。

“构造一个对象”包含建立对象初始状态的含义，并不等于只为对象申请内存。

先为 `Date` 提供无参和三参数两个构造函数：

```cpp
// Date.h
#pragma once
#include <iostream>

namespace wind
{
    class Date
    {
    public:
        Date();
        Date(int year, int month, int day);
        void Print();

    private:
        int _year;
        int _month;
        int _day;
    };
}

// Date.cpp
#include "Date.h"

wind::Date::Date()
{
    std::cout << "正在调用构造函数“Date”-2" << std::endl;
    _year = 2;
    _month = 2;
    _day = 2;
}

wind::Date::Date(int year, int month, int day)
{
    std::cout << "正在调用构造函数“Date”-1" << std::endl;
    _year = year;
    _month = month;
    _day = day;
}

void wind::Date::Print()
{
    std::cout << _year << "/" << _month << "/" << _day << std::endl;
}

// main.cpp
#include "Date.h"

int main()
{
    wind::Date d1(1, 2, 3);
    wind::Date d2;
    d1.Print();
    d2.Print();
}
```

三个成员仍然在函数体中赋值，便于与 `Init` 对照。类中原来的 `Init` 已不再需要作为创建后的必经步骤，这里先将它移除。成员初始化还有更直接的写法，后续再展开。

构造函数和普通成员函数一样可以重载。`d1` 提供三个参数，匹配三参数版本；`d2` 没有提供参数，匹配无参版本。

![两个构造函数的调用结果](https://img.mdwind.online/md/202409251304835.png)

无参创建对象时，要注意对象定义的写法。不要在对象名后照搬一对空括号，否则下面的 `f` 会被解释为函数名：

```cpp
wind::Date d;   // 定义对象，调用可无参调用的构造函数。
wind::Date f(); // 声明函数：无参数，返回 wind::Date；这里没有创建对象。
```

### 默认构造函数与全缺省参数

“默认构造函数”指可以不提供实参就调用的构造函数。编译器自动提供的无参构造函数属于这一类；自己写的无参构造函数，以及所有参数都有缺省值的构造函数，也都是默认构造函数。

前面的两个版本可以合并为一个全缺省版本：

```cpp
namespace wind
{
    class Date
    {
    public:
        Date(int year = 1, int month = 1, int day = 1);
        void Print();

    private:
        int _year;
        int _month;
        int _day;
    };
}

wind::Date::Date(int year, int month, int day)
{
    _year = year;
    _month = month;
    _day = day;
}
```

缺省参数写在声明处，类外定义不重复填写。这个版本允许 `Date d;`、`Date d(2024);`、`Date d(2024, 10);` 和 `Date d(2024, 10, 1);`。

采用它以后，应移除原先独立的 `Date()`。否则，无实参调用会同时匹配两个构造函数，产生二义性。

### 参数类型正确，不代表日期合法

`int` 只说明参数可以表示整数，不会替日期类检查“月份是否在 1 到 12 之间”“二月是否有这一天”。这些约束来自日期模型，需要类的实现自行维护。

本节采用公历规则，约定年份从 1 开始，不讨论历史历法切换。先提供一个返回月份天数的普通函数：

```cpp
// Date.cpp 中需要包含 <cassert>。
namespace wind
{
    int DayList(int year, int month)
    {
        assert(year >= 1);
        assert(month >= 1 && month <= 12);

        const static int days[13] =
            { 0, 31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31 };

        if (month == 2 &&
            (year % 400 == 0 || (year % 4 == 0 && year % 100 != 0)))
        {
            return 29;
        }
        return days[month];
    }
}
```

数组下标直接对应月份，0 号元素不使用。`static` 使数组具有静态存储期，不随每次函数调用重新创建；`const` 表达表中数据不应被修改的约束。

构造函数可以据此检查日期：

```cpp
wind::Date::Date(int year, int month, int day)
{
    if (year < 1 || month < 1 || month > 12 ||
        day < 1 || day > DayList(year, month))
    {
        std::cout << "错误：非法的日期参数！" << std::endl;
    }

    _year = year;
    _month = month;
    _day = day;
}
```

这里约定调用者传入合法日期。检查条件中的 `||` 具有短路特性，只有年份和月份合法后才会调用 `DayList`，避免先用非法月份访问数组。

本节对非法日期只打印提示，随后仍按输入值给成员赋值。这是为了在讲解构造函数时保留简单的代码形式，并不表示提示以后对象就恢复了合法状态。后文的比较与日期运算仍以输入合法为前提，非法对象不应进入正常运算示例。

接口的使用者需要遵守调用约定；本节暂不展开输入错误后的恢复流程。这里也能看到，构造函数没有普通的返回值，不能像 `bool Init(...)` 那样直接返回成功与否。以后可以进一步讨论由专门的创建接口报告结果，或者记录对象有效性等设计，当前先把注意力放在初始化机制上。

### 让构造函数接替栈的 Init

回到上一课时的栈，最直接的迁移是把 `Init` 的工作放入构造函数：

```cpp
// stack.h 中用 stack(); 替换 void Init();。
wind::stack::stack()
{
    _p = nullptr;
    _top = _capacity = 0;
}
```

这样，`wind::stack s;` 创建后就是空栈。第一次 `push` 发现容量为 0，仍通过上一课时的 `Ext` 申请两个元素的空间；其后按原容量的两倍扩容，失败时返回 `false`，由 `push` 停止本次写入。

如果能估计待处理的数据量，也可以在创建时提供初始容量，减少后续扩容次数。这里的容量表示预留空间，不表示已经存在这么多个有效元素。

除了新建空栈，再提供一个接管现有动态数组的指针参数。只传容量时创建空栈；传入数组时，约定数组的前 `capacity` 个元素均有效，栈接管整块内存。

接管的必须是可以用 `realloc` 和 `free` 管理的动态数组；交给栈后，由栈负责后续扩容与释放，调用者不再自行释放。这个接口容易让资源控制权不够清楚，因此本节保留它用于观察构造方式，但不建议把接管外部数组作为普通栈接口的默认设计。

```cpp
// stack.h 中的声明，用它替换前面的 stack();。
// 仅传 capacity：预留空间，初始元素个数为 0。
// 同时传 pArr：接管动态数组，capacity 也必须等于有效元素个数。
stack(int capacity = 2, p_stack_data pArr = nullptr);
```

```cpp
// stack.cpp 需要 <cassert>、<cstdlib> 和 <cstdio>。
wind::stack::stack(int capacity, p_stack_data pArr)
{
    assert(capacity >= 0);
    assert(pArr == nullptr || capacity > 0);

    _p = nullptr;
    _top = _capacity = 0;

    if (pArr != nullptr)
    {
        _p = pArr;
        _top = _capacity = capacity;
        return;
    }

    if (capacity == 0)
        return;

    p_stack_data p = (p_stack_data)std::realloc(
        nullptr, sizeof(stack_data) * capacity);
    if (p == nullptr)
    {
        std::perror("栈构造申请内存失败");
        return;
    }

    _p = p;
    _capacity = capacity;
}
```

默认初始容量仍为 2，传入 0 则保留延迟到第一次入栈才申请空间的行为。`realloc(nullptr, size)` 在这里承担申请内存的工作，不会把申请到的元素空间自动填成有效数据，因此新建空栈的 `_top` 仍为 0。

内存申请失败时，这里只打印提示并结束构造函数体。由于一开始已把 `_p` 设为空、两个计数设为 0，对象会保留为空栈，后续析构仍然安全。但请求的初始容量并未建立，不能把“对象已经存在”当成“预分配一定成功”。

内存不足不一定来自容器实现错误，申请失败后的处理仍应有清楚的约定。本节先采用打印提示的过渡办法，不在这里引入之后才会说的异常，也不让容器直接结束进程。后续再讨论怎样让调用者明确判断创建结果。

### const 成员函数

上一课时已经知道，成员函数通过 `this` 与当前对象建立联系。先为栈增加一个输出已有元素的普通成员函数 `Print`，声明为 `void Print();`。现在定义一个常对象，再尝试调用它：

```cpp
const wind::stack s;
s.Print(); // 若 Print 没有 const 限定，这里不能通过编译。
```

![常对象调用普通成员函数时的诊断](https://img.mdwind.online/md/202410011714762.png)

问题来自对象的访问权限。常对象的地址类型是 `const stack*`，但普通 `Print` 中的 `this` 类型是 `stack*`，允许通过它修改栈对象。若允许常对象调用这样的成员函数，就相当于把只读访问扩大成可写访问，因此编译器拒绝这个调用。

即使 `Print` 的函数体没有真正修改成员，调用者也需要从声明中知道它是否允许修改对象。解决方法是在成员函数参数列表后面加上 `const`：

```cpp
// stack.h 中的声明。
void Print() const;

// stack.cpp 中的定义。
void wind::stack::Print() const
{
    for (int i = 0; i < _top; ++i)
        std::cout << _p[i] << " ";
    std::cout << std::endl;
}
```

这样，函数中的 `this` 类型就是 `const stack*`，不再通过它直接修改当前对象的成员，常对象的调用也就不会扩大权限。声明和定义都应加上 `const`。

![常成员函数调用的实验输出](https://img.mdwind.online/md/202410011724304.png)

因此，如果一个成员函数只是观察对象、不需要改变对象状态，就应将它声明为常成员函数。普通对象可以调用常成员函数，常对象也可以调用；需要修改对象的 `push`、`Pop` 则保持原来的形式。

本例相应地把 `IsEmpty`、`ReadTop` 和 `Print` 都声明为常成员函数，日期类的 `Print` 也作同样处理：

```cpp
// stack.h
bool IsEmpty() const;
bool ReadTop(stack_data& val) const;
void Print() const;

// Date.h
void Print() const;

// Date.cpp
void wind::Date::Print() const
{
    std::cout << _year << "/" << _month << "/" << _day << std::endl;
}
```

实际使用中，即使一个对象原本没有被 `const` 修饰，也经常需要通过常引用来访问它。例如，向函数传递对象时，可以使用引用，避免为形参复制一份对象。如果这个函数只需要读取对象，还可以给引用加上 `const`，限制它通过该引用修改对象。此时，虽然原对象仍然可以修改，但在这个函数内部，通过常引用只能对它进行只读访问。因此，通过该引用调用的成员函数，也需要带有 `const` 限定。这就是我们需要把 `Print`、`IsEmpty` 等只读操作声明为常成员函数的另一个常见原因。

### 编译器提供的默认构造

若类没有自己声明构造函数，编译器会隐式声明默认构造函数；是否能使用它，还要看各个成员是否具备相应的初始化条件。自己声明了构造函数后，编译器不会再替我们额外补一个无参版本。

```cpp
class Date
{
public:
    Date(int year, int month, int day);
    // 其余成员省略。
};

Date d; // 编译失败：没有能无参调用的构造函数。
```

对于上一课时那种只有三个整数、没有成员初始值的 `Date`，局部定义 `Date d;` 不会初始化这三个整数。它们所在空间可能仍保留之前的数据，但程序不能把这些未初始化的值当成有效日期来使用。

![未初始化成员的观察记录之二](https://img.mdwind.online/md/202409251549640.png)

也可以直接在类定义中提供成员默认初始值，先观察写法与效果，其具体初始化规则后续再展开：

```cpp
namespace wind
{
    class Date
    {
    public:
        void Print() const;

    private:
        int _year = 1;
        int _month = 1;
        int _day = 1;
    };
}
```

给三个成员设置初始值以后，即使没有自己编写构造函数，创建日期对象时也会使用这些值，于是得到 `1/1/1`。

![使用成员默认初始值后的实验结果](https://img.mdwind.online/md/202409251555249.png)

如果成员本身是类对象，编译器提供的默认构造函数还会调用各成员类型的构造函数。这里借用“两个栈组织队列”的结构，只观察成员创建，不展开队列实现：

```cpp
// queue.h
#pragma once
#include "stack.h"

namespace wind
{
    class Queue
    {
    private:
        stack _pushStack;
        stack _popStack;
    };
}

// main.cpp
#include "queue.h"

int main()
{
    wind::Queue q;
}
```

`Queue` 没有自己声明构造函数。创建 `q` 时，它的默认构造会依成员声明顺序，分别默认构造 `_pushStack` 与 `_popStack`。因为 `stack` 的构造函数有全缺省参数，这两次调用都能无参完成。

如果 `stack` 只有必须传参的构造函数，而 `Queue` 又没有提供相应的初始化信息，`Queue q;` 就无法完成构造。因此，成员类是否提供可访问的默认构造函数，会直接影响外层类能否直接采用默认构造。自己编写外层构造函数时，同样需要完成成员对象的构造，相关写法后续再讨论。

## 析构函数

### 生命周期结束时清理资源

构造函数让对象在创建时获得初始状态，析构函数则负责对象销毁阶段的清理。它的名字是 `~类名`，没有返回类型，也没有显式参数。普通类的析构函数不能像构造函数那样靠不同参数列表进行重载。

对于当前的局部对象，离开所在作用域时会自动调用析构函数，不要求调用者再手动调用 `Dest`。把上一课时栈的清理逻辑迁移过来：

```cpp
// stack.h 中用 ~stack(); 替换 void Dest();。
wind::stack::~stack()
{
    std::free(_p);
    _p = nullptr;
    _top = _capacity = 0;
}
```

`free` 释放的是 `_p` 指向的动态元素空间，不是 `stack` 对象自己的存储。把指针和计数清零只是整理本对象的状态，并不会让别处保存的旧指针也自动变为空。

析构函数负责清理对象所管理的资源，并不只限于动态内存。一个整数可能只是普通数据，也可能代表某种资源标识；一个指针可能管理一块动态内存，也可能只是借用地址。编译器无法只凭类型替我们判断应当释放什么。

因此，编译器自动生成的析构函数不会看到指针就自动调用 `free`。`Date` 的三个整数没有额外清理工作，通常不必自己写析构函数；`stack` 直接管理一块动态内存，就需要明确释放它。

对于能自行管理资源的成员对象，外层对象析构时会自动调用该成员的析构函数。例如，`Queue` 中两个 `stack` 会各自清理所管理的空间，外层不必重复释放。成员对象的析构在外层析构函数体执行后进行，顺序与成员构造顺序相反；成员构造顺序的具体规则后续再讲。

### 局部对象的析构顺序

同一作用域中正常完成构造的局部对象，退出时按构造完成的逆序析构：

```cpp
int main()
{
    wind::Date d;
    wind::stack s;
} // 先析构 s，再析构 d。
```

析构时机由作用域和对象的生命周期决定。在函数内部另设一个语句块，其中的局部对象也会在离开该语句块时析构。

## 拷贝构造函数

### 按值传参为什么暴露资源问题

构造与析构接入生命周期后，资源不容易因漏写 `Dest` 而泄漏。但另一个问题随之变得明显：复制对象时，资源该怎样处理？

先假设已经为栈写了构造与析构，但还没有自己编写拷贝构造。执行下面的按值传参：

```cpp
void Observe(wind::stack s)
{
    std::cout << s.IsEmpty() << std::endl;
}

int main()
{
    wind::stack s1;
    s1.push(10);
    Observe(s1);
}
```

形参 `s` 是一个新对象，不是 `s1` 的别名。编译器默认生成的拷贝构造函数会复制 `_top`、`_capacity` 的值，也会复制 `_p` 保存的地址，却不会自动再申请另一块元素空间。指针在不同程序中有不同用途，编译器不能据此替我们决定资源的复制方式。

于是，两个不同的栈对象拥有各自的指针成员，却指向同一块动态内存。形参销毁时，它的析构函数释放这块空间；`s1._p` 随即成为悬空指针。随后访问元素会触及已经释放的内存，`s1` 析构时再次释放它，又会产生重复释放。

形参和实参的生命周期彼此独立，但这里两个指针指向同一块动态资源，因此其中一个对象释放资源后，另一个对象也会受到影响。

### 浅拷贝与深拷贝

对于当前这个直接拥有动态数组的栈，可以这样区分：浅拷贝复制指针值，两个对象仍指向同一块数组；深拷贝则另外申请一块数组，把有效元素复制过去，使两个栈分别管理自己的资源。

“深”应结合资源结构理解，不必机械地理解为复制所有能沿指针找到的东西。这里的元素就是 `int`，只有栈对象与其动态数组这两层需要考虑。

如果函数只是观察栈，不需要拥有副本，可以改用常引用：

```cpp
void Observe(const wind::stack& s)
{
    std::cout << s.IsEmpty() << std::endl;
}
```

此时没有新的栈对象被复制出来，引用本身也不会在函数结束时替原栈释放资源。常引用还能限制函数通过这个接口改变原栈的逻辑状态。

如果确实需要独立副本，就应实现符合所有权约定的拷贝构造函数。它仍是构造函数，名字仍为类名，参数使用同类对象的引用。这里不需要修改源对象，因此采用 `const stack&`：

```cpp
// stack.h 中增加 stack(const stack& s);。
// stack.cpp 还需要包含 <cstring>。
wind::stack::stack(const stack& s)
{
    _p = nullptr;
    _top = _capacity = 0;

    if (s._capacity == 0)
        return;

    p_stack_data p = (p_stack_data)std::realloc(
        nullptr, sizeof(stack_data) * s._capacity);
        
    if (p == nullptr)
    {
        std::perror("栈拷贝申请内存失败");
        return;
    }

    if (s._top > 0)
        std::memcpy(p, s._p, sizeof(stack_data) * s._top);

    _p = p;
    _top = s._top;
    _capacity = s._capacity;
}
```

先独立申请空间，再复制有效元素，最后建立新对象的状态。空容量单独处理，不把零字节申请的返回值误判成普通的内存不足。

这里用 `memcpy` 复制 `int` 元素是合适的：新栈已经有独立的数组，只需把有效整数复制进去。但不能由此推广到所有元素类型。若元素自身还管理动态资源，直接复制它的字节可能把内部资源地址一并复制过去，使不同元素共用同一资源，随后发生重复释放。因此，将栈元素改为更复杂的类时，需要同时重新考虑元素复制和生命周期管理。

申请副本空间失败时，同样只打印提示并保留一开始建立的空栈状态，不再继续复制元素。这保证当前对象仍能安全析构，但没有完成请求的复制，不能把这个过渡方案理解为完整的错误处理接口。后续再讨论如何明确报告这一结果。

拷贝构造的参数需要是引用。若写成 `stack(stack s)`，创建按值形参本身又需要复制一个 `stack`，逻辑上会反复依赖同一个复制过程，所以这种声明不能通过编译。`stack(const stack* p)` 则是另一种普通构造函数，不是拷贝构造函数。

### 哪些地方使用拷贝构造

```cpp
wind::stack s1;
s1.push(10);

wind::stack s2(s1);  // 用 s1 构造新对象 s2。
wind::stack s3 = s1; // 同样是初始化新对象，不是给已有对象赋值。
```

按值传递一个已有对象，也会创建形参副本。两种对象初始化写法是否带 `=`，不改变“目标对象正在创建”这一点。

加入深拷贝后，副本和原栈的动态空间独立，分别析构不会重复释放同一块内存。

### 默认拷贝构造能完成什么

对于这里的普通类，编译器提供的拷贝构造按成员进行复制。整数复制数值，指针复制地址；成员本身是类对象时，使用该成员类型的相应拷贝构造。它不负责猜测“这根指针是不是需要深拷贝”。

因此，只有三个整数的 `Date` 可以使用默认拷贝构造。`Queue` 的两个成员若都能正确复制，外层通常也不必重复编写相同工作。反过来，如果成员不能复制，外层也不会凭空得到一个可用的复制方式。

成员默认初始值不能替代复制：复制日期时，需要取得源日期的年、月、日，而不是重新把目标日期初始化为 `1/1/1`。

## 运算符重载与赋值

### 用函数定义对象的运算含义

类对象需要比较、赋值或参与其他有意义的运算。运算符重载让这些操作可以写成与内置类型相近的表达式，其实现仍然是函数。

例如，日期比较可以写成 `d1 != d2`。若定义为成员函数，左操作数就是当前对象，右操作数通过显式参数传入：

```cpp
// Date.h 中增加：
bool operator!=(const Date& d) const;

// Date.cpp 中定义：
bool wind::Date::operator!=(const Date& d) const
{
    return _year != d._year || _month != d._month || _day != d._day;
}
```

对这个成员重载，`d1 != d2` 可以写成 `d1.operator!=(d2)`，通常仍采用更自然的运算符形式。比较只读取两个日期，不改变任何一方，因此形参使用 `const Date&`，函数末尾也加上 `const`。常引用还避免了按值传参时构造对象副本的工作。

类的成员函数可以访问同类其他对象的私有成员，因此这里可以读取 `d._year`。私有访问限制由所在代码的访问资格决定，不是只能访问 `this` 自己的成员。

运算符重载必须涉及类或枚举类型，不能凭空创造新运算符，也不能改变原有运算符的优先级、结合性和操作数个数。并不是所有运算符都能重载；当前先掌握日期需要的这些。

复用 `!=` 可以实现 `==`；按年、月、日逐级比较可以实现 `>`，其余比较继续复用：

```cpp
bool wind::Date::operator==(const Date& d) const
{
    return !(*this != d);
}

bool wind::Date::operator>(const Date& d) const
{
    if (_year != d._year)
        return _year > d._year;
    if (_month != d._month)
        return _month > d._month;
    return _day > d._day;
}

bool wind::Date::operator<(const Date& d) const
{
    return d > *this;
}

bool wind::Date::operator>=(const Date& d) const
{
    return !(*this < d);
}

bool wind::Date::operator<=(const Date& d) const
{
    return !(*this > d);
}
```

这些函数的声明也要放入类的公开区域。比较以日期已经合法为前提，不应每次比较都重新修补非法的成员值。

### 拷贝构造与拷贝赋值的区别

```cpp
wind::Date d1(2024, 10, 1);
wind::Date d2 = d1; // d2 正在创建：拷贝构造。
wind::Date d3;
d3 = d1;           // d3 已经存在：拷贝赋值。
```

赋值运算符可以自己定义为：

```cpp
// Date.h 中增加 Date& operator=(const Date& d);。
wind::Date& wind::Date::operator=(const Date& d)
{
    if (this != &d)
    {
        _year = d._year;
        _month = d._month;
        _day = d._day;
    }
    return *this;
}
```

返回 `Date&`，使结果继续代表左操作数，支持 `d1 = d2 = d3` 等写法，也避免为返回结果另造一个日期副本。

`return *this` 返回当前对象的引用。赋值操作完成后，目标对象仍然存在，因此可以继续通过这个引用访问它。

`this != &d` 检查是否自赋值。对于这里三个整数的直接赋值，不加检查也不会出错；加入它可以跳过无意义的工作。持有资源的类则需要结合具体实现认真处理自赋值。

`Date` 实际上可以使用编译器提供的成员赋值。这里手写是为了观察机制。默认赋值会给整数赋值、复制指针地址，并对类成员调用相应的赋值操作。

C 也允许兼容结构体类型之间赋值，这与按成员复制数据的默认赋值行为相近。这里新学到的是：C++ 类可以通过函数，按自身设计定义赋值行为。

### 栈的赋值还要处理已有资源

为栈补了深拷贝构造，还不代表 `s2 = s1` 已经安全。赋值前，`s2` 可能正管理另一块动态内存。直接复制指针既会丢掉这块旧资源，又会让两个栈指向同一块新资源。

本例采用先准备新资源、成功后再替换旧资源的顺序：

```cpp
// stack.h 中增加 stack& operator=(const stack& s);。
wind::stack& wind::stack::operator=(const stack& s)
{
    if (this == &s)
        return *this;

    p_stack_data p = nullptr;
    if (s._capacity > 0)
    {
        p = (p_stack_data)std::realloc(
            nullptr, sizeof(stack_data) * s._capacity);
            
        if (p == nullptr)
        {
            std::perror("栈赋值申请内存失败");
            return *this;
        }

        if (s._top > 0)
            std::memcpy(p, s._p, sizeof(stack_data) * s._top);
    }

    std::free(_p);
    _p = p;
    _top = s._top;
    _capacity = s._capacity;
    return *this;
}
```

若新空间申请失败，旧资源尚未释放，目标栈保持原状。成功后再释放目标原先的空间、接入副本，两个对象继续各自负责各自的资源。

这也说明构造、复制和销毁应一起考虑：一个类若直接拥有动态内存，通常不能只写析构函数，而不检查它的拷贝构造和赋值是否符合所有权约定。

## 日期的加减与自增、自减

### 运算含义与返回方式

日期加一个天数可以得到另一个日期；两个日期相减可以得到相差天数；日期加日期则没有本节需要表达的含义，不必强行提供运算。

先确定接口职责：

| 运算               | 是否改变左侧日期 | 返回方式                 |
| ------------------ | ---------------- | ------------------------ |
| `d += n`、`d -= n` | 改变             | 返回 `Date&`，仍代表 d。 |
| `d + n`、`d - n`   | 不改变           | 返回新的 `Date` 值。     |
| `++d`、`--d`       | 改变             | 返回改变后的 d 的引用。  |
| `d++`、`d--`       | 改变             | 返回改变前日期的副本。   |
| `d1 - d2`          | 不改变           | 返回带符号的天数差。     |

`+=`、`-=` 可以直接更新对象，`+`、`-` 则在副本上复用这些操作。这样实现便于集中处理日期进位与借位，也符合“复合赋值修改原对象、普通加减产生新结果”的使用习惯。返回引用与返回指针要分清，下面使用的是引用。

### 通过月份进位和借位

先实现非负天数的前进。年、月、日始终先表示一个合法日期，计算当前月份还剩多少天。若天数足够，就停在当前月；否则跨过月末，进入下一月的第一天：

```cpp
wind::Date& wind::Date::operator+=(int num)
{
    assert(num != INT_MIN);
    if (num < 0)
        return *this -= -num;

    while (num > 0)
    {
        int remaining = DayList(_year, _month) - _day;
        if (num <= remaining)
        {
            _day += num;
            break;
        }

        num -= remaining + 1;
        _day = 1;
        ++_month;
        if (_month > 12)
        {
            _month = 1;
            ++_year;
        }
    }
    return *this;
}
```

例如，1 月 30 日加 2 天，当月还剩 1 天；再多走一步便到 2 月 1 日，共消耗 2 天。每次跨月后重新调用 `DayList`，因此跨入二月、跨年等情况自然使用对应年月的天数。

这里没有先把任意大的 `num` 一次性加到 `_day`，而是按月消耗天数，避免这次中间加法本身溢出。负数转交减法处理。

倒退时，如果要减去的天数小于当前日号，就仍在本月；否则先退到上个月最后一天，再处理剩余天数：

```cpp
wind::Date& wind::Date::operator-=(int num)
{
    assert(num != INT_MIN);
    if (num < 0)
        return *this += -num;

    while (num > 0)
    {
        if (num < _day)
        {
            _day -= num;
            break;
        }

        num -= _day;
        --_month;
        if (_month < 1)
        {
            assert(_year > 1);
            --_year;
            _month = 12;
        }
        _day = DayList(_year, _month);
    }
    return *this;
}
```

例如，2024 年 3 月 1 日减 1 天，先消耗当前日号所代表的这一步，月份退到 2 月，再取得 2024 年 2 月的最后一天，即 29 日。借的是上一个月的天数，因此一定先调整年月，再查询月长。

本节的算术接口处理通常范围内的日期与天数，约定结果仍在年份和计数类型的可表示范围内，且不早于公元 1 年。代码用 `<climits>` 中的 `INT_MIN` 断言排除不能直接取相反数的最小整数，避免负数转换时溢出；不在这里引入超大日期范围的另一套表示。

### 普通加减复用复合赋值

```cpp
wind::Date wind::Date::operator+(int num) const
{
    Date result = *this;
    result += num;
    return result;
}

wind::Date wind::Date::operator-(int num) const
{
    Date result = *this;
    result -= num;
    return result;
}
```

`result` 是独立的局部对象，修改它不影响原日期。函数必须返回值，不能返回 `result` 的引用，因为它会在函数退出时结束生命周期。

### 前置与后置的区分

前置自增、自减没有显式参数；后置版本用一个 `int` 形参作区分标记。对于 `d++`，重载调用相当于 `d.operator++(0)`，编译器提供标记实参 0。形参名可以省略，因为实现不需要使用这个值。

```cpp
wind::Date& wind::Date::operator++()
{
    return *this += 1;
}

wind::Date wind::Date::operator++(int)
{
    Date old = *this;
    *this += 1;
    return old;
}

wind::Date& wind::Date::operator--()
{
    return *this -= 1;
}

wind::Date wind::Date::operator--(int)
{
    Date old = *this;
    *this -= 1;
    return old;
}
```

前置直接返回更新后的对象引用；后置需要先保留旧值，再修改原对象，最后返回旧值副本。不需要旧值时，使用前置形式表达得更直接。

### 两个日期之间的天数差

先用较小的日期逐日追赶较大的日期，累计步数，再恢复原本的方向：

```cpp
int wind::Date::operator-(const Date& d) const
{
    Date later = *this;
    Date earlier = d;
    int sign = 1;

    if (later < earlier)
    {
        later = d;
        earlier = *this;
        sign = -1;
    }

    int count = 0;
    while (earlier != later)
    {
        ++earlier;
        ++count;
    }
    return sign * count;
}
```

相同日期得到 0，左侧较晚得到正数，左侧较早得到负数。这个实现直观，时间复杂度随相差天数增长，适合当前验证日期运算的阶段。跨度很大时，可以再研究按累计日数计算的算法。

### 使用固定日期验证行为

用固定输入便于重复核对结果，也避免把当前时间、平台专用时间接口和日期运算混在同一个示例里：

```cpp
#include "Date.h"
#include <iostream>

int main()
{
    wind::Date d(2024, 2, 28);
    (++d).Print();                  // 2024/2/29
    (d++).Print();                  // 2024/2/29，返回更新前的日期。
    d.Print();                      // 2024/3/1
    (--d).Print();                  // 2024/2/29
    (d - 1).Print();                // 2024/2/28，d 自身不变。

    wind::Date a(2023, 3, 1);
    (a - 1).Print();                // 2023/2/28
    (wind::Date(2023, 12, 31) + 1).Print(); // 2024/1/1

    const wind::Date b(2024, 3, 1);
    std::cout << b - wind::Date(2024, 2, 28) << '\n'; // 2
    std::cout << wind::Date(2024, 2, 28) - b << '\n'; // -2

    wind::Date copy = b;            // 拷贝构造。
    copy = a;                       // 拷贝赋值。
    copy += -1;
    copy.Print();                   // 2023/2/28
}
```

非法日期可以单独用于观察提示，不参与后续的正常日期运算：

```cpp
// 单独观察非法日期的提示。
wind::Date invalid(2023, 2, 29); // 平年二月没有 29 日，打印提示后仍保存传入的值。
```

`stack.cpp` 包含 `stack.h`、`<cassert>`、`<cstdlib>`、`<cstdio>`、`<cstring>`与 `<iostream>`。前文构造、析构、拷贝构造和赋值的定义各保留一次，其余函数如下：

```cpp
bool wind::stack::Ext()
{
    int newCapacity = _capacity == 0 ? 2 : _capacity * 2;
    p_stack_data p = (p_stack_data)std::realloc(_p, sizeof(stack_data) * newCapacity);
    if (p == nullptr)
    {
        std::perror("stack.Ext realloc fail");
        return false;
    }
    _p = p;
    _capacity = newCapacity;
    return true;
}

bool wind::stack::push(stack_data val)
{
    if (_top == _capacity && !Ext())
    {
        return false;
    }
    _p[_top++] = val;
    return true;
}

bool wind::stack::IsEmpty() const
{
    if (_top == 0)
        return true;
    else
        return false;
}

bool wind::stack::ReadTop(stack_data& val) const
{
    if (IsEmpty())
        return false;
    else
    {
        val = _p[_top - 1];
        return true;
    }
}

bool wind::stack::Pop()
{
    if (IsEmpty())
        return false;
    else
    {
        _top--;
        return true;
    }
}

bool wind::stack::ReadPop(stack_data& val)
{
    if (IsEmpty())
        return false;
    else
    {
        ReadTop(val);
        return Pop();
    }
}


void wind::stack::Print() const
{
    for (int i = 0; i < _top; ++i)
        std::cout << _p[i] << " ";
    std::cout << std::endl;
}
```

栈的容量与计数继续使用课时一的 `int`，扩容逻辑也保持不变；当前示例针对通常规模的数据，不试图在这一课时完成通用容器的全部容量边界设计。

### 栈的使用

```cpp
#include "stack.h"
#include <iostream>

void Observe(const wind::stack& s)
{
    s.Print();
}

int main()
{
    wind::stack s1;
    int values[] = { 2, 4, 6, 8 };
    for (int value : values)
    {
        if (!s1.push(value))
            return 1;
    }

    wind::stack s2 = s1; // 拷贝构造，资源独立。
    s2.Pop();
    Observe(s1);         // 2 4 6 8
    Observe(s2);         // 2 4 6

    wind::stack s3(0);
    s3 = s1;             // 赋值给已有对象，资源仍独立。
    s3 = s3;             // 自赋值。
    s3.push(10);
    Observe(s3);         // 2 4 6 8 10

    wind::stack_data value;
    while (s1.ReadPop(value))
        std::cout << value << " ";
    std::cout << std::endl; // 8 6 4 2
} // 三个栈分别析构，不再手动调用 Dest。
```
