# 模版初阶

## 泛型编程

C++中的函数作为某一过程的实现方式，常常会遇到这种困扰：两个函数的逻辑十分相似，不过由于函数的参数必须指定类型，所以必须拆成两个函数写，尽管C++c存在重载函数，函数名可以相同，但还是要一个一个写，太麻烦了，此时模版就可以发挥作用了。

```cpp
// 如何实现一个通用的交换函数呢？

// swap.hpp
#pragma once

namespace wind {
inline void swap(int& here, int& there) {
    int tmp = here;
    here = there;
    there = tmp;
}

inline void swap(double& here, double& there) {
    double tmp = here;
    here = there;
    there = tmp;
}

inline void swap(char& here, char& there) {
    char tmp = here;
    here = there;
    there = tmp;
}

}  // namespace wind
```

这里我们把函数的实现(定义)写到了 hpp 中, hpp 表示文件里面既有声明, 又有定义, 那为什么要进行文件合并操作呢? 这主要和模板的后续知识有关, 我们稍后再说; 为了避免 hpp 被多个 cpp 包含, 从而违反 ODR 原则(我们在类和对象中专门说过), 这里使用 inline 对函数实现进行修饰.

接下来我们使用模板来表述 swap, 模版的使用方法是关键字`template<class name>`或者`template<typename name>`，其中的`name`是对类型的代称。名字取合法的就行，能表现具体用途的更好。多个类型是这样的`template<class T1, class T2>`。此处的函数模板定义是不需要加内联的, 之后我们在说模板机制的大致逻辑会回答这个问题.

```cpp
#pragma once

namespace wind {
template <typename T>
void swap(T& here, T& there) {
    T tmp = here;
    here = there;
    there = tmp;
}
}  // namespace wind
```

当调用模版函数时，编译器会依据参数的类型和函数模版生成一份对应的函数。

```cpp
#include "swap.hpp"

int main(){
    int i = 1, j = 10;
    double m = 1.25, n = 6.25;
    wind::swap(i, j);
    wind::swap(m, n);
    return 0;
}
```

函数可以有模版，类也可以有。对于各种数据结构来说，有时需要存储不同类型的数据，比如，我们想生成一个用来存储整型和浮点型的栈，此时类模版就非常有用，`typedef`则要再写一份。

```cpp
typedef int SDate, * pSDate;
class Stack
{
public:
	Stack(size_t sz = 4, SDate* pArr = nullptr);
	~Stack();
	Stack(const Stack& s);
	Stack& operator=(const Stack& s);
	void Push(int val);
	void Extend();
	void Print()const;
private:
	SDate* _val;
	size_t _top;
	size_t _capacity;
};
```

```cpp
template<class SDate>
class Stack
{
public:
	Stack(size_t sz = 4, SDate* pArr = nullptr);
	~Stack();
	Stack(const Stack& s);
	Stack& operator=(const Stack& s);
	void Push(int val);
	void Extend();
	void Print()const;
private:
	SDate* _val;
	size_t _top;
	size_t _capacity;
};
```

```cpp
int main()
{
	Stack<int> i;
	Stack<double> j;
	return 0;
}
```

这里没有传参，所以要显式的告诉编译器到底用什么类型，此时的`Stack<int>`和`Stack<double>`实际上已经是两个不同的类了。

### 模板定义放在头文件中，为什么不违反 ODR？

我们知道，头文件被多个源文件包含后，其中的内容会分别进入不同的翻译单元。如果把一个普通的非内联函数定义放在头文件里，就可能在链接时遇到重复定义。

但是，模板的定义通常也放在头文件里。这看起来同样是在多个翻译单元中定义了相同的东西，为什么就没有问题呢？

我认为，可以从**语言规则**和**编译链接过程**两个层面理解。

#### 从语言规则来看

单一定义规则并不是简单地说“所有东西都只能定义一次”。对于模板，C++ 允许同一个模板的定义出现在多个翻译单元中，只要这些定义满足相应条件。

例如：

```
// add.hpp#pragma oncetemplate <typename T>T add(T a, T b){    return a + b;}
```

当不同的源文件包含这个头文件时，每个翻译单元都会看到这份模板定义。这些定义共同描述的是同一个模板，不能因为它们出现在多个翻译单元中，就直接认定违反了 ODR。

当然，既然说的是“同一个模板”，各处的定义就需要保持一致。例如，定义需要满足相同的记号序列，以及其中的名字查找等相关要求。把定义放在同一个头文件中，再由各个源文件包含，就是一种自然的组织方式。

#### 从编译和链接来看

模板和普通函数还有一个实际使用上的区别：模板中的类型参数需要先确定，编译器才能生成对应的具体函数。

假设 `a.cpp` 和 `b.cpp` 都包含了 `add.hpp`，并且都使用了 `add<int>`。这两个源文件是分别编译的，因此，编译器处理 `b.cpp` 时，通常并不知道 `a.cpp` 是否已经实例化过 `add<int>`。结果就是：两个翻译单元都可能各自生成一份 `add<int>` 的代码。

等到链接时，编译器和链接器会按照模板的规则处理这些实例。常见的做法是合并重复生成的代码，让各处对 `add<int>` 的使用最终对应同一个函数。

类模板也是类似的：同一个类模板使用相同的模板实参，得到的是同一个类特化。不过，用这个类创建的不同对象，仍然各自拥有自己的数据。

#### 把两个层面放在一起

从语言规则上说，**符合条件的模板定义可以出现在多个翻译单元中**；从编译链接的实际过程来看，**各翻译单元可能分别生成同一个实例，再由工具链协调处理**。

因此，模板放在头文件中，看上去好像定义了很多次，但这些定义共同描述同一个模板，相同模板实参对应的也不是几个互相冲突的函数。这是模板能够以这种方式组织代码的原因。

## 模版实例化

从上面的过程中可以看到，编译器不是直接使用模版运行程序，而是依据实际需求，在需要具体函数或类的时候生成一份，这个过程就叫做模版的实例化。

实例化分为两种：隐式实例化和显式实例化。其实上面的过程我们已经体会到了

```cpp
// 隐式实例化：让编译器根据实参推演模板参数的实际类型
template<class T>
    T Add(const T& left, const T& right)
{
    return left + right;
}
int main()
{
    int a1 = 10, a2 = 20;
    double d1 = 10.0, d2 = 20.0;
    Add(a1, a2);
    Add(d1, d2);
 /*
该语句不能通过编译，因为在编译期间，当编译器看到该实例化时，需要推演其实参类型
通过实参a1将T推演为int，通过实参d1将T推演为double类型，但模板参数列表中只有一个T，
编译器无法确定此处到底该将T确定为int 或者 double类型而报错
注意：在模板中，编译器一般不会进行类型转换操作，因为一旦转化出问题，编译器就需要背黑锅
Add(a1, d1);
*/
    // 此时有两种处理方式：1. 用户自己来强制转化 2. 使用显式实例化
    Add(a, (int)d);
    return 0;
}


// 显式实例化：在函数名后的<>中指定模板参数的实际类型
int main(void)
{
    int a = 10;
    double b = 20.0;
    // 显式实例化
    Add<int>(a, b);
    return 0;
}
// 如果类型不匹配，编译器会尝试进行隐式类型转换，如果无法转换成功编译器将会报错。
```

## 函数模版的匹配原则

函数模版的实例化是在找不到需要函数的情况下才会进行，如果用户已经写出了需要的函数，那编译器就不会再根据模版再生成一份。例如，下文的加法函数模版和整型加法函数可以同时存在，默认情况下，编译器会调用已经写了的整型加法函数。(当然你也不要恶意提问, 问我在下面代码中, 具体函数定义和模板定义是不是在一个 hpp 里面的, 我这里的意思当然是都放在同一个 hpp 里的)

```cpp
// add.hpp
#pragma once

#include <iostream>

namespace wind {

// 引用底层有开销, 起码有个指针
// 所以直接就用 int 了
// 但这并不是主要的注意点
inline int add(int v1, int v2) {
    std::cout << "int" << std::endl;
    return v1 + v2;
}

// 模板不清楚具体类型, 所以干脆常引用算了
// 如果是自定义类, 没有实现加法是他自己的事
template <typename T>
T add(const T& v1, const T& v2) {
    std::cout << "template" << std::endl;
    return v1 + v2;
}
}  // namespace wind

// main.cpp
#include "add.hpp"

int main() {
    auto i = wind::add(1, 5);
    std::cout << i << std::endl;
    // 如果存在特殊需求, 就是要用模板实例化出的
    // 使用显式实例化即可
    auto j = wind::add<int>(1, 5);
    std::cout << j << std::endl;
    return 0;
}

```

## 声明和定义分离

模版声明和定义分离时，二者都必须设置模版，同时由于没有具体的类，只有类模版，所以用到类时不能光写模版类名，比如`className`，而是要写成`className<T>`的形式。这在返回值和域的突破中都有体现，以上文中的栈`Stack`为例，声明前面已经写过，省略不写，这里只写定义。(其实不用管这个, 我们实际上都是写在一个 hpp 里的, 模板, 后面我们会说, 模板, 不管是 函数模板, 亦或者 类模板, 都要写到一个文件里, 我们实际上一般做法是直接写定义, 也就是声明实现都直接写一块)

```cpp
template<class SDate>
wind::Stack<SDate>::Stack(size_t sz, SDate* pArr)
{
	_capacity = sz;
	if (pArr == nullptr)
	{
		SDate* p = (SDate*)realloc(pArr, sizeof(SDate) * _capacity);
		if (p == nullptr)
		{
			perror("Error: Bulid fail");
			exit(-1);
		}
		_val = p;
		_top = 0;
	}
	else
	{
		_val = pArr;
		_top = _capacity;
	}
}

template<class SDate>
wind::Stack<SDate>::~Stack()
{
	free(_val);
	_val = nullptr;
	_top = _capacity = 0;

}

template<class SDate>
wind::Stack<SDate>::Stack(const Stack & s)
{
	_capacity = s._capacity;
	_top = s._top;
	SDate* p = (SDate*)realloc(nullptr, sizeof(SDate) * _capacity);
	if (p == nullptr)
	{
		perror("Error: Copy fail");
		return;
	}
	memcpy(p, s._val, sizeof(SDate) * _top);
	_val = p;
}

template<class SDate>
wind::Stack<SDate>& wind::Stack<SDate>::operator=(const Stack& s)
{
	SDate* p = (SDate*)realloc(_val, sizeof(SDate) * s._capacity);
	if (p == nullptr)
	{
		perror("Error: Assign fail");
		return *this;
	}
	_capacity = s._capacity;
	_top = s._top;
	memcpy(p, s._val, sizeof(SDate) * _top);
	_val = p;
	return *this;
}

template<class SDate>
void wind::Stack<SDate>::Push(int val)
{
	if (_top == _capacity)
	{
		Extend();
	}

	_val[_top++] = val;
}

template<class SDate>
void wind::Stack<SDate>::Extend()
{
	size_t NewCapacity = _capacity == 0 ? 4 : _capacity * 2;
	SDate* p = (SDate*)realloc(_val, sizeof(SDate) * NewCapacity);
	if (p == nullptr)
	{
		perror("Error: Align fail");
		return;
	}
	_val = p;
	_capacity = NewCapacity;
}

template<class SDate>
void wind::Stack<SDate>::Print()const
{
	size_t present = 0;
	for (; present < _top; present++)
	{
		std::cout << _val[present] << " ";
	}
	std::cout << std::endl;
}
```

一个具体的自定义类型是由类模版实例化出的，所以类名和自定义类型不是同一概念。域的突破要用自定义类型而不是类名。

**除此之外，还要注意，模版的声明和定义即使分离了，也要尽可能地写在同一文件中，否则极容易出问题。**
