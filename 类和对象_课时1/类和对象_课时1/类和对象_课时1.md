# 类和对象：课时一

C 语言主要采用面向过程的方式组织程序：把问题拆成若干步骤，再通过函数完成这些步骤。C++ 保留了这种编程方式，同时提供了类等语言机制，使我们能够把相关的数据和操作组织到一起，用对象及其交互描述问题。

这两种思路可以在同一个程序中配合使用。学习类和对象，可以先从已经熟悉的结构体出发，观察 C++ 怎样把数据、操作以及访问规则结合起来。

## 类的引入

在 C 中，结构体可以把相关数据组合成一种类型，但不能直接在结构体内部定义成员函数。操作结构体的函数通常定义在外部，并通过指针接收要操作的对象。例如，栈的入栈操作可以写成 `Push(&s, value)`。

C++ 扩展了 `struct` 的能力，允许在其中声明和定义成员函数。用 `struct` 定义的类型本身就是类类型，也可以使用 `class` 定义类，二者的默认访问权限稍后讨论。

类体中声明的变量称为成员变量，也称数据成员；类体中声明的函数称为成员函数。对于下面这种普通成员函数，可以直接通过成员名访问当前对象的数据，也可以调用同一个类中的其他成员函数。

下面用一个存储 `int` 的栈观察这种写法。这里暂时沿用 C 中的动态内存管理方式，并通过 `Init`、`Dest` 显式管理资源，以便把注意力放在类的基本结构上。对象使用前必须调用 `Init`，使用后调用 `Dest`；持有动态内存的栈对象暂时不要直接复制，复制与资源管理的问题留到后续讨论。

成员变量采用前置下划线的命名风格，便于和形参、局部变量区分。`_top` 表示已有元素个数，同时也是下一次入栈的位置；非空时，栈顶元素位于 `_p[_top - 1]`。

```cpp
#include <cstdlib>
#include <cstdio>
#include <iostream>

namespace wind
{
    typedef int stack_data, * p_stack_data;
    struct stack
    {
        // 成员函数
        void Init()
        {
            _p = nullptr;
            _top = _capacity = 0;
        }

        void Dest()
        {
            std::free(_p);
            _p = nullptr;
            _top = _capacity = 0;
        }

        bool Ext()
        {
            int newCapacity = _capacity == 0 ? 2 : _capacity * 2;
            p_stack_data p = (p_stack_data)std::realloc(_p, sizeof(stack_data) * newCapacity);
            if (p == nullptr)
            {
                std::perror("stack.Ext realloc fail");
                return false;
            }
            _p = p;
            _capacity = newCapacity;
            return true;
        }

        bool push(stack_data val)
        {
            if (_top == _capacity && !Ext())
            {
                return false;
            }
            _p[_top++] = val;
            return true;
        }

        bool IsEmpty()
        {
            if (_top == 0)
                return true;
            else
                return false;
        }

        bool ReadTop(stack_data& val)
        {
            if (IsEmpty())
                return false;
            else
            {
                val = _p[_top - 1];
                return true;
            }
        }

        bool Pop()
        {
            if (IsEmpty())
                return false;
            else
            {
                _top--;
                return true;
            }
        }

        bool ReadPop(stack_data& val)
        {
            if (IsEmpty())
                return false;
            else
            {
                ReadTop(val);
                return Pop();
            }
        }

        // 成员变量
        p_stack_data _p;
        int _top;
        int _capacity;
    };
}

int main()
{
    wind::stack s;
    s.Init();
    int Array[] = { 2,4,6,8 };
    for (auto tem : Array)
    {
        if (!s.push(tem))
        {
            s.Dest();
            return 1;
        }
    }
    while (!s.IsEmpty())
    {
        wind::stack_data val;
        s.ReadPop(val);
        std::cout << val << " ";
    }
    std::cout << std::endl;
    s.Dest();
}
```

## 访问限定符

上面的成员都可以在类外直接访问。调用者既可以使用 `s.push(value)`，也可以直接修改 `s._top`。后一种方式容易破坏栈自身的状态：例如，随意增大 `_top`，就可能让后续操作越过已经分配的空间。

类需要区分对外提供的接口和内部维护的数据。C++ 使用访问限定符控制成员的访问权限：

| 限定符 | 当前阶段需要掌握的含义 |
| --- | --- |
| `public` | 类外可以通过对象访问，是对外接口常用的权限。 |
| `private` | 类外普通代码不能直接访问，类自身的成员函数可以访问。 |
| `protected` | 类外普通代码同样不能直接访问，与 `private` 的区别在学习继承时展开。 |

访问限定符从出现的位置开始生效，直到下一个访问限定符或类体结束。它规定的是成员的访问权限，不会另外建立一个作用域。

`struct` 和 `class` 都能使用这三种权限，也都能包含成员变量和成员函数。当前需要掌握的区别是：`struct` 的成员默认是 `public`，`class` 的成员默认是 `private`。二者的默认继承权限也不同，留到继承部分讨论。`struct` 并非仅为兼容 C 才存在，C++ 中也经常用它定义以公开数据为主的类型。

因此，只把上例的 `struct` 改成 `class`，类外的 `s.Init()` 等调用就会因成员默认私有而编译失败。可以将供调用者使用的操作放到 `public` 区域，把成员变量放到 `private` 区域：

```cpp
#include <cstdlib>
#include <cstdio>
#include <iostream>

namespace wind
{
    typedef int stack_data, * p_stack_data;
    class stack
    {
    public:
        // 成员函数
        void Init()
        {
            _p = nullptr;
            _top = _capacity = 0;
        }

        void Dest()
        {
            std::free(_p);
            _p = nullptr;
            _top = _capacity = 0;
        }

    private:
        bool Ext()
        {
            int newCapacity = _capacity == 0 ? 2 : _capacity * 2;
            p_stack_data p = (p_stack_data)std::realloc(_p, sizeof(stack_data) * newCapacity);
            if (p == nullptr)
            {
                std::perror("stack.Ext realloc fail");
                return false;
            }
            _p = p;
            _capacity = newCapacity;
            return true;
        }

    public:
        bool push(stack_data val)
        {
            if (_top == _capacity && !Ext())
            {
                return false;
            }
            _p[_top++] = val;
            return true;
        }

        bool IsEmpty()
        {
            if (_top == 0)
                return true;
            else
                return false;
        }

        bool ReadTop(stack_data& val)
        {
            if (IsEmpty())
                return false;
            else
            {
                val = _p[_top - 1];
                return true;
            }
        }

        bool Pop()
        {
            if (IsEmpty())
                return false;
            else
            {
                _top--;
                return true;
            }
        }

        bool ReadPop(stack_data& val)
        {
            if (IsEmpty())
                return false;
            else
            {
                ReadTop(val);
                return Pop();
            }
        }

    private:
        // 成员变量
        p_stack_data _p;
        int _top;
        int _capacity;
    };
}

int main()
{
    wind::stack s;
    s.Init();
    int Array[] = { 2,4,6,8 };
    for (auto tem : Array)
    {
        if (!s.push(tem))
        {
            s.Dest();
            return 1;
        }
    }
    while (!s.IsEmpty())
    {
        wind::stack_data val;
        s.ReadPop(val);
        std::cout << val << " ";
    }
    std::cout << std::endl;
    s.Dest();
}
```

此时，类外代码仍然可以调用公开接口，但不能直接修改 `_p`、`_top` 和 `_capacity`。`Ext` 只为入栈操作服务，也可以收进私有区域，避免调用者依赖内部扩容步骤。

封装还依赖接口本身的正确性。例如，扩容失败时，`push` 必须停止写入并把失败结果传回调用者，不能只在 `Ext` 中打印错误后继续执行。

## 类的声明与成员函数定义分离

简短的成员函数可以直接定义在类体中；需要组织多个源文件时，也可以在头文件里保留类定义和成员函数声明，把成员函数的定义放到源文件中。两种方式都很常见，应根据代码规模和组织需要选择。

下面将同一个栈拆成三个文件：

```cpp
// stack.h
#pragma once
#include <cstdlib>
#include <cstdio>
#include <iostream>

namespace wind
{
    typedef int stack_data, * p_stack_data;
    class stack
    {
    public:
        // 成员函数
        void Init();
        void Dest();
        bool push(stack_data val);
        bool IsEmpty();
        bool ReadTop(stack_data& val);
        bool Pop();
        bool ReadPop(stack_data& val);

    private:
        bool Ext();

        // 成员变量
        p_stack_data _p;
        int _top;
        int _capacity;
    };
}

// stack.cpp
#include"stack.h"

void wind::stack::Init()
{
    _p = nullptr;
    _top = _capacity = 0;
}

void wind::stack::Dest()
{
    std::free(_p);
    _p = nullptr;
    _top = _capacity = 0;
}

bool wind::stack::Ext()
{
    int newCapacity = _capacity == 0 ? 2 : _capacity * 2;
    p_stack_data p = (p_stack_data)std::realloc(_p, sizeof(stack_data) * newCapacity);
    if (p == nullptr)
    {
        std::perror("stack.Ext realloc fail");
        return false;
    }
    _p = p;
    _capacity = newCapacity;
    return true;
}

bool wind::stack::push(stack_data val)
{
    if (_top == _capacity && !Ext())
    {
        return false;
    }
    _p[_top++] = val;
    return true;
}

bool wind::stack::IsEmpty()
{
    if (_top == 0)
        return true;
    else
        return false;
}

bool wind::stack::ReadTop(stack_data& val)
{
    if (IsEmpty())
        return false;
    else
    {
        val = _p[_top - 1];
        return true;
    }
}

bool wind::stack::Pop()
{
    if (IsEmpty())
        return false;
    else
    {
        _top--;
        return true;
    }
}

bool wind::stack::ReadPop(stack_data& val)
{
    if (IsEmpty())
        return false;
    else
    {
        ReadTop(val);
        return Pop();
    }
}

// main.cpp
#include"stack.h"

int main()
{
    wind::stack s;
    s.Init();
    int Array[] = { 2,4,6,8 };
    for (auto tem : Array)
    {
        if (!s.push(tem))
        {
            s.Dest();
            return 1;
        }
    }
    while (!s.IsEmpty())
    {
        wind::stack_data val;
        s.ReadPop(val);
        std::cout << val << " ";
    }
    std::cout << std::endl;
    s.Dest();
}
```

`void wind::stack::Init()` 中，`wind::stack::` 指明这里定义的是命名空间 `wind` 下 `stack` 类中已经声明的成员函数。若只写 `void Init()`，定义的就是另一个普通函数，无法对应到类中的声明。

类具有自己的作用域。限定名将这个函数定义与类关联起来，所以函数体中的 `_p`、`_top` 和 `_capacity` 可以按类成员查找，并通过当前对象访问。类作用域与命名空间作用域都参与名字查找，但类并不是真正的命名空间，用命名空间做类比是一种更便于理解的方式。

## 类的实例化

定义类是在描述一种类型；用这个类型创建对象，才会得到具体保存数据的实体。这与 C 中先定义结构体类型、再创建结构体对象的区别是一致的。

```cpp
wind::stack s1;
wind::stack s2;

s1.Init();
s2.Init();
```

这里创建了两个 `wind::stack` 对象，也可以说对这个类进行了实例化。类定义中的 `_p`、`_top`、`_capacity` 描述了对象应有的数据成员，`s1` 和 `s2` 则各自拥有一份这些成员。

以这里的 `_top` 为例，`wind::stack::_top` 不能直接给出某个栈的元素个数，因为它没有指定对象；通过 `s1._top` 才指定了 `s1` 的成员，但还要满足访问权限。上面的 `_top` 是私有成员，因此类外代码应通过公开接口了解或操作栈的状态。

创建对象和调用 `Init` 也要分清：执行 `wind::stack s1;` 时对象已经存在，但本例中的指针和整数成员尚未得到有效的初始值。`s1.Init()` 是为已有对象建立初始状态。目前显式调用 `Init` 只是一种过渡方式，后续会遇到专门负责相关工作的特殊成员函数。

## 类对象的存储

对于本文这样的类，每个对象各自保存成员变量，成员函数的代码则不需要为每个对象复制一份。

例如，`s1` 和 `s2` 各有自己的指针、元素个数和容量。两者都执行入栈操作时，遵循的是同一套函数逻辑，但逻辑处理的对象状态不同，所以可以分别保存不同的数据。

这里还要区分栈对象本身与它申请的动态内存。对象里的 `_p` 是一个指针成员，指向另外分配的元素空间；`sizeof(s1)` 会计入指针本身，却不会把指针所指的那块空间算进去。

### 对象大小与内存对齐

当前示例的布局可以沿用 C 结构体的分析思路：成员按布局规则安排，并可能因对齐而出现填充。因此，对象大小与成员的类型、排列和对齐要求有关，不能简单地认为所有成员大小相加就是最终结果。函数代码不按每个对象一份的方式计入 `sizeof`。

### 没有数据成员的类

既然函数代码不计入对象大小，只有成员函数的类以及空类会有多大？

```cpp
class A
{
public:
    void f() {}
private:
    int _a;
};

class B
{
public:
    void f() {}
};

class C
{};

int main()
{
    std::cout << sizeof(A) << std::endl;
    std::cout << sizeof(B) << std::endl;
    std::cout << sizeof(C) << std::endl;
    return 0;
}
```

![image-20240924184637251](https://img.mdwind.online/md/202409241846412.png)

对于这里的普通独立对象，空类对象也必须占据非零空间。常见实现中，`sizeof(B)` 和 `sizeof(C)` 都是 1；这是常见结果，不是所有实现必须取 1 的要求。

这样，即使对象没有数据成员，也仍然具有可区分的身份。例如：

```cpp
B m;
B n;
std::cout << (&m != &n) << '\n'; // 输出 1
```

`m` 和 `n` 是两个不同的对象，可以分别取地址并区分。这个字节也不代表编译器偷偷添加了一个供程序使用的普通成员变量。

## this 指针

成员函数使用同一套代码，而各个对象的数据又是独立的，那么一次调用怎样确定要操作哪个对象？

先看一个日期类：

```cpp
// Date.h
#pragma once

#include <iostream>

namespace wind
{
    class Date
    {
    public:
        void Init(int year, int month, int day);
        void Print();
    private:
        int _year;
        int _month;
        int _day;
    };
}

// Date.cpp
#include"Date.h"

void wind::Date::Init(int year, int month, int day)
{
    _year = year;
    _month = month;
    _day = day;
}

void wind::Date::Print()
{
    std::cout << _year << "/" << _month << "/" << _day << std::endl;
}

// test.cpp
#include"Date.h"

int main()
{
    wind::Date d1,d2;
    d1.Init(1, 1, 1);
    d2.Init(2, 2, 2);
    d1.Print();
    d2.Print();
    return 0;
}
```

`d1.Init(1, 1, 1)` 和 `d2.Init(2, 2, 2)` 调用的是同一个成员函数，但 `_year`、`_month` 和 `_day` 应分别写入两个对象。

调用这里的成员函数时，调用会隐含地提供当前对象，函数体中通过 `this` 得到指向该对象的指针。在 `d1.Init(...)` 中，`this` 指向 `d1`；在 `d2.Init(...)` 中，它指向 `d2`。

因此，下面两种函数体在本例中表达同样的成员访问：

```cpp
void wind::Date::Init(int year, int month, int day)
{
    _year = year;
    _month = month;
    _day = day;
}

// 另一种写法，与上面的定义二选一。
void wind::Date::Init(int year, int month, int day)
{
    this->_year = year;
    this->_month = month;
    this->_day = day;
}
```

`this` 并不是对象中额外保存的指针成员，所以不需要在计算对象大小时为它再加一个指针的空间。它随成员函数调用关联到当前对象。

### 把隐含的对象传递展开理解

可以用下面的伪代码理解调用机制：

```text
源代码：d1.Init(1, 1, 1)
概念展开：Init实现(&d1, 1, 1, 1)

Init实现(当前对象的指针, year, month, day)
    通过这个指针写入对象的三个成员
```

这个展开只是解释模型，不能直接把原调用改写成 `Date::Init(&d1, ...)`，也不能在普通成员函数的参数表中自行声明一个名为 `this` 的参数。

在这里的成员函数中，`this` 的类型是 `Date*`，可以通过它修改当前对象的成员，但不能给 `this` 本身赋值，使它转而指向另一个对象。

成员函数中调用同一对象的其他成员函数，也可以省略 `this->`。例如，在 `Init` 中调用 `Print()`，本例中就是调用 `this->Print()`。

类外的 `d1.Print()` 和 `(&d1)->Print()` 同样都指定 `d1` 为调用对象。`.` 和 `->` 仍然是成员访问运算符；对成员函数进行调用时，对象与调用之间的关联体现为隐含的对象传递。函数代码不放在对象内部，不影响它在语言层面属于类的成员。

目前这些成员函数的调用都会隐含地传入对象地址。这种与对象绑定的调用方式在某些场景下也会带来限制，相应的处理方式留到后续讨论。

`lea` 只计算地址，没有读取整个对象。两次调用的函数目标都是 `0x555555555240`，传入的对象地址不同，这正对应“代码相同、处理的对象不同”。

再把对象地址与当前栈帧联系起来。函数序言先保存 `rbp`，再把当前 `rsp` 复制给 `rbp`，随后通过 `subq $0x20, %rsp` 为局部存储等用途预留 32 字节。此后，负偏移表示比当前 `rbp` 更低的地址。

在这份具体记录中，三个 `int` 共占 12 字节，可以得到下列范围：

| 用途 | 相对 `rbp` 的字节范围 | 依据 |
| --- | --- | --- |
| `d2` | `rbp - 0x1c` 至 `rbp - 0x11` | 第二次调用前计算的对象起始地址。 |
| `d1` | `rbp - 0x10` 至 `rbp - 0x05` | 第一次调用前计算的对象起始地址。 |
| 本次编译生成的返回值槽 | `rbp - 0x04` 至 `rbp - 0x01` | `movl $0x0, -0x4(%rbp)`。 |

其中，`rbp - 0x04` 处是本次编译为 `main` 生成的返回值槽，入口处先将它置为 0。在这份记录中，后续并未从这个槽读取返回值，而是在函数末尾通过 `xorl %eax, %eax` 直接把返回值 0 放入 `eax`。因此，这个槽虽然已经预留并初始化，实际返回时却没有用到它。这个布局属于当前编译结果，不必推广成所有函数都必须具备的固定结构。

这些位置属于本次编译的具体结果。对象地址通过哪个寄存器传递，取决于调用约定；调试构建中它可能随后被保存到栈上，优化构建中也可能保留在寄存器，甚至不再有独立存储位置。因此，不应把 `this` 固定描述成“存放在栈帧里的参数”。

## 空指针调用成员函数

理解了对象地址的传递，还需要区分机器指令的执行现象与语言允许的调用。

```cpp
#include <iostream>
class A
{
public:
    void Print()
    {
        std::cout << "Print()" << '\n';
    }

private:
    int _a;
};

int main()
{
    A* p = nullptr;
    p->Print(); // 可能观察到输出，但语言规则上属于未定义行为。
}
```

这段代码可能通过编译，也可能在某次运行中打印出内容。沿着前面的实现模型，可以理解这种现象：生成的代码可能只是传入了一个空的对象地址，而函数体又没有通过它读取或写入数据，所以这次执行没有触发访问异常。

从语言规则来看，这个调用属于未定义行为：空指针没有提供成员函数调用所需的有效对象。因此，“这次运行能够输出”可以作为实现现象来分析，但不能据此将它视为合法、可依赖的调用方式。

再看一个不同的问题，仍使用上面的 `A`：

```cpp
int main()
{
    A* p = nullptr;
    p->_a;
}
```

这段代码中的 `_a` 是私有成员，类外的 `main` 不能直接访问，因此会产生编译错误。

若将 `_a` 改为公有，就可以继续观察编译器是否为这条未使用结果的表达式生成实际访存指令。不过，空指针访问成员在语言规则上仍属于未定义行为；是否生成访存指令、运行时是否崩溃，是另一个层面的观察。

## 封装

类把相关的数据与操作组织起来，访问权限则用于划分公开接口与内部实现。这些机制共同支持封装。

以栈为例，调用者通过入栈、出栈、判空等接口使用对象，类内部负责维护 `_p`、`_top` 与 `_capacity` 的关系。只要这些关系受到正确维护，调用者就不需要在每次入栈时重新处理容量和下标问题。

把成员变量设为私有，只完成了其中一部分工作。接口还应有明确的使用约定，正确处理失败，并避免把调用者不需要操纵的内部步骤暴露出去。例如，本例要求先初始化再使用，扩容失败必须终止本次入栈，销毁后应清空指针和计数。这些都直接影响封装后的对象能否可靠使用。

C 也能通过头文件、独立源文件和不透明结构体等方式隐藏实现。C++ 在语言层面提供了成员函数与访问控制，使这些组织规则可以直接写进类定义，并由编译器检查。两种语言都需要设计清楚接口及其约束，访问限定符不能替代这项设计。
